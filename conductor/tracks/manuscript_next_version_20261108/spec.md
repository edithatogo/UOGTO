# Specification — next version of the existing resource paper

## Problem and objective

The existing June-dated `docs/paper/paper.tex` and supplement retain twelve
accepted mappings, 448 rejected rows, ten competency questions and older graph
counts. The reconciled November evidence has four accepted structural narrow
matches, six unresolved mappings, 450 rejected rows and 21 competency queries.
The original search's negative ontology route missed a verified GTO predecessor;
metadata discovery, acquisition, term charting and execution must be separated.
Current quality metrics need explicit namespace and coverage denominators.

Produce the next version of this same resource paper, integrating source
attribution and measured evidence while preserving the historical snapshot as
history. The delivered [revision plan](../../../docs/paper/next-version-plan-20261108.md)
defines C01–C12, RQs, comparator strata, coverage metrics, controls, prospective
held-out cases, artifact lineage and publication boundaries. Planning is complete;
implementation is pending. The user requested planning rather than writing the
new manuscript now.

## Scope and requirements

1. Retain the resource contribution and actual existing section structure. Correct
   the abstract, Results, Methods, Discussion, glossary, figures, supplement and
   availability claims consistently in a future deliberate manuscript revision.
2. Freeze dated historical and reanalysis inputs separately. Never relabel the
   retained 4,046 term rows or 460 candidates as including new November sources.
   Count source unions only after deduplication and evidence-state accounting.
3. Consume the comprehensive source protocol, discovery seeds, bibliography and
   attribution ledger, plus OCS.02–12 receipts relevant to each claim. Record
   unavailable artifacts and unsupported concepts without implying exhaustive
   acquisition or complete strategic coverage.
4. Bind source locators, licenses, concept lineage, manuscript citations and
   measured outputs in a claim-evidence ledger. Update source-builder inputs
   alongside generated CSL; verify authorship and other metadata against primary
   records. Cite original precedents and derivative/adapted artifacts explicitly.
5. Report annotation, class/property, shape, example, query and module counts with
   declared universes. The current report's 23/307 target-class coverage and
   33/211 property-path coverage differ from 30/30 linked examples and the
   restricted 17/17 linked-module denominator.
6. Distinguish source-evidence missingness from an examined ontology-support gap.
   Use applicable/unknown/excluded/unsupported statuses and numerator/denominator
   values, with externally specified cases if actual held-out evidence is claimed.
7. Report paired valid/mutated controls and exact CQ answers for claims actually
   tested. Agent checks are internal; no independent agreement or expert
   adjudication is fabricated. Scaffold performance/calibration is not a result.
8. Explain corrected solution/computation/result categories, causal direction,
   static/dynamic versus representation/scheduling, and real reference-tool origin.
   No LLM, Rust, solver, adapter or native-simulation claim without matching evidence.
9. Keep later interoperability/frontier papers separate. Existing SGC/FRT owners
   supply real adapter/provider receipts only if those optional claims are retained.
   The next resource paper does not depend on completion of all FRT leaves.
10. Reuse existing validation, citation, caption, PDF and arXiv package checks, then
    inspect the rendered candidate and retain clean exact-head provenance. The
    repository state says `not_submitted`; no public arXiv version or acceptance
    is asserted without external evidence.

## Interfaces and ownership

- **OCS** owns acquisition, discovery completeness, concept crosswalks, lineage
  and case/coverage evaluation. This track integrates their bounded receipts,
  including explicit unavailable/pending outcomes, into the paper.
- **SGC** owns executable subsets, identity, round trips and consumer receipt
  scopes. **FRT** owns actual external-library and frontier experiments.
- **Paignia** owns runtime/adapters; **Kairos** is optional native simulation;
  UOGTO owns language-neutral semantics and reference fixtures.
- **MNV** owns manuscript/supplement structure, citation and evidence integration,
  new candidate snapshot manifests, figure/table consistency and publication package.
- Existing source/research metadata remains authoritative within its stated scope.
  Provider versions and publication identifiers are consumed, never invented.

## Acceptance and exclusions

The planning deliverable is accepted when the five authored files exist, their
links/dependencies are coherent, current facts match inspected artifacts and future
commands/outcomes are explicitly prospective. Root records overall repository
validation for this planning change. MNV.00 may close; MNV.01–12 remain pending.

Future implementation is accepted when retained claims have traceable support,
new and historical counts reconcile separately, scoped controls and publication
checks pass on the recorded head, and the new PDF/source bundle is inspected.
Missing empirical or adapter evidence narrows the paper's claims rather than
blocking unrelated resource corrections. The manuscript integration track cannot
mark OCS/SGC/FRT completed or confer publication acceptance.

No canonical paper rewrite, new benchmark execution, source acquisition,
provider implementation, new major dependency, upload, release, commit or push is
part of this planning deliverable. External upload and journal decisions remain
outside repository completion. Routine implementation uses existing review and
CI without another approval chain. If a future leaf exceeds five authored files
or gains an independent outcome, split it before implementation; generated
outputs are enumerated separately. A coherent revision can be rolled back through
its normal changeset while preserving the historical source/artifact snapshot.
